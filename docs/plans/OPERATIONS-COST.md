# تشغيل وتكلفة النسخة الأولى

آخر مراجعة: 2026-09-21.

## الوضع الحالي

- قاعدة البيانات والأونلاين على خطة Free بسعر 0 دولار حاليًا. الحدود الرسمية وقت المراجعة: 2 مليون رسالة Realtime، و500 ألف استدعاء وظائف، و5 GB نقل بيانات، و200 اتصال Realtime متزامن، و500 MB لقاعدة البيانات، و50 ألف مستخدم نشط شهريًا. الخطة المجانية لا تحاسب تجاوزات؛ قد توقف أو تحد الخدمة، ومشروعها قد يتوقف بعد أسبوع بلا نشاط.
- استضافة الويب منشورة، لكن أداة المشروع لم تعرض نوع الخطة أو فاتورتها. تُراجع صفحة Usage/Billing يدويًا قبل أي ترقية.
- خدمة relay للصوت ليست في خطة TURN فعالة حسب آخر تحقق موثق؛ لذلك تكلفتها الحالية صفر لكن المسار الاحتياطي غير مضمون. لا شراء لخطة قبل قياس الحاجة.
- لا توجد إعلانات أو مشتريات أو تحليل صوت بالذكاء الاصطناعي في النسخة الحالية.
- أول شهرين: أقصى مخاطرة تشغيل مدفوعة 1000 جنيه في الشهر. أي ترقية أو خدمة جديدة قرار يدوي، ولا يعتمد على إيراد إعلاني غير محصل.

## ما يقاس تلقائيًا من الآن

`usage_daily` يجمع يوميًا أعداد الغرف والماتشات المكتملة والمهجورة، دقائق الماتش ودقائق اللاعبين. لا يحتفظ باسم أو معرّف لاعب أو كود غرفة أو دور أو رسالة أو صوت. القياس يبدأ بعد نشر migration `usage_metering`؛ الأرقام السابقة ليست backfill.

تقرير الشهر للمشغّل فقط:

```sql
select * from public.usage_month_report(date_trunc('month',now())::date);
select * from public.usage_alerts order by created_at desc limit 20;
```

يوجد حد proxy محافظ قدره 3000 ماتش بدأ في الشهر، مبني على تقدير بنية المشروع 600 رسالة للماتش مقابل حد مليوني رسالة. تنبيهات 50% و75% و90% و100% تُسجل مرة واحدة لكل مستوى. Dashboard المورد هو الحقيقة لأن عدد اللاعبين وإعادة الاتصال يغيران الاستهلاك.

## إيقاف التوسع دون قطع اللعب

عند اقتراب الحد الحقيقي أو وجود مشكلة تشغيل، يُوقف المشغّل **إنشاء غرف جديدة فقط**:

```sql
update public.operations_control
set new_rooms_enabled=false,reason='operator capacity hold',updated_at=now()
where singleton=true;
```

اللاعب يرى أن الإنشاء متوقف مؤقتًا ويمكنه دخول غرفة موجودة أو اللعب بدون إنترنت. الماتشات والرومات الموجودة لا تُغلق. إعادة الفتح بتغيير القيمة إلى `true` ومسح السبب.

## مراجعة أسبوعية، 10 دقائق

1. افتح Usage لكل من الأونلاين واستضافة الويب وخدمة TURN إن فُعّلت.
2. سجّل: Realtime messages، Edge invocations، egress، peak connections، database size، web bandwidth، TURN GB، والفاتورة المستحقة بالعملة الأصلية.
3. قارن بتقرير اللعبة. اختلاف النسب طبيعي؛ القفزة غير المفسرة تستدعي وقف إنشاء غرف جديدة والتحقيق.
4. عند 50% راقب مرتين أسبوعيًا؛ 75% يوميًا؛ 90% أوقف أي حملة وقيّم الحد؛ 100% أوقف الغرف الجديدة إن كانت الخدمة ستتعطل أو ستتجاوز السقف.
5. لا تقطع ماتشًا بدأ، ولا تطفئ الصوت فجأة. يمكن إبقاء اللعب النصي لأن الصوت غير أساسي.

## متى ندفع؟

لا ترقية لمجرد التنزيلات. القرار يحتاج عدد شلل عائدة، تكلفة لكل لاعب نشط، وإيراد محصل. بعد وجود دخل منتظم، هدف التشغيل ألا يتجاوز 20% من الإيراد بعد رسوم المتجر والاستردادات وقبل التشغيل. إذا تجاوزت التكلفة هذا المستوى، نصلح الاستهلاك أو التسعير قبل زيادة الجمهور.
